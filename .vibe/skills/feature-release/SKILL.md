# Feature Release

Ao finalizar a implementação de qualquer funcionalidade neste projeto, execute o
fluxo completo de release abaixo, nesta ordem. Só prossiga para a etapa seguinte
se a anterior tiver sucesso.

## 1. Build do binário (release)

Gere o binário e o pacote com o script de release do projeto:

```bash
powershell.exe -ExecutionPolicy Bypass -File scripts/package.ps1
```

O script roda `cargo build --release` e copia o resultado para
`dist/NeoChat.exe`. Alternativa mínima (sem empacotar):
`cargo build --release` e confira que `target/release/neochat.exe` existe.

- Se o build falhar, corrija os erros de compilação e repita. Não commitar código que não compila.
- `dist/` e `target/` estão no `.gitignore` — nunca os inclua no commit.

## 2. Commit

- Revise o que mudou com `git status` e `git diff` e adicione apenas os arquivos relacionados à funcionalidade.
- Mensagem no padrão conventional commits já usado no repositório:
  - `feat: <descrição curta da funcionalidade>` (ou `fix:`, `chore:` conforme o caso).
- Use sempre o formato heredoc com a assinatura:

```bash
git commit -m "$(cat <<'EOF'
feat: <descrição da funcionalidade>

Generated by Mistral Vibe.
Co-Authored-By: Mistral Vibe <vibe@mistral.ai>
EOF
)"
```

## 3. Push

```bash
git push origin master
```

- Confirme antes que o build do passo 1 passou e o commit do passo 2 foi criado.
- Se o push for rejeitado, rode `git pull --rebase origin master` e tente novamente; nunca use `--force`.

## 4. Resumo final

Informe ao usuário: o que foi commitado, o hash do commit, se o push foi
concluído e o caminho do binário gerado (`dist/NeoChat.exe`).
